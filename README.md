# Ruang Sales — pilot WhatsApp manual

Ruang kerja sales dengan autentikasi PostgreSQL, pembatasan akses cabang, inbox pesan teks, QR untuk menautkan **satu nomor milik sales dengan persetujuan pemilik**, dan balasan manual. Gateway yang dipakai ialah [rmyndharis/OpenWA 0.29.1](https://github.com/rmyndharis/OpenWA/releases/tag/v0.29.1) (`ENGINE_TYPE=baileys`), **bukan** `@open-wa/wa-automate`. Ini integrasi WhatsApp **tidak resmi**: nomor dapat dibatasi atau diblokir. Jangan memakai nomor utama sebelum pilot dan persetujuan yang jelas.

## Jalankan pilot lokal

Butuh Node.js 22+, Docker Compose, dan port lokal 5432, 3001, 5173. Port gateway **tidak** diekspos ke host. Seluruh perintah dari root proyek.

1. `npm ci`. Salin `.env.example` ke `.env` (jangan commit). Isi `POSTGRES_PASSWORD`, `DATABASE_URL` (host `127.0.0.1`), `API_DATABASE_URL` (host `db`), `ADMIN_EMAIL`, `ADMIN_PASSWORD` (12+ karakter), dan `OPENWA_WEBHOOK_SECRET` dengan nilai acak 32+ karakter. URL-encode karakter khusus pada password di URL koneksi PostgreSQL. `OPENWA_API_KEY` diperlukan sebelum API dimulai.
2. Biarkan `OPENWA_API_KEY` sementara berisi placeholder di `.env`, lalu jalankan database dan gateway **tanpa menghubungkan telepon**: `docker compose up -d db openwa`. Jangan memulai API dengan placeholder. Gateway menyimpan key awal di `/app/data/.api-key`: baca secara privat dengan `docker compose exec openwa cat /app/data/.api-key`, pindahkan nilainya ke `OPENWA_API_KEY` di `.env`, lalu simpan rahasia itu di secret manager. Key operator tanpa pembatasan chat/sesi dapat dibuat lewat API gateway untuk pemakaian jangka panjang; jangan mengirim key via browser atau URL. Hindari mencetak key di log/screenshot bersama.
3. `npm run db:migrate` menjalankan migrasi `001`, `002`, dan `003_outbound.sql`. `npm run admin:create` membuat super admin sekali (tidak mereset akun lama). Kedua perintah memakai `DATABASE_URL` host lokal.
4. `docker compose up -d --build api` untuk API yang terhubung ke gateway di jaringan Docker privat. `npm run dev` untuk web di `http://localhost:5173`; login dengan akun admin dari langkah pertama. Buat cabang dan akun sales dengan nomor dalam format internasional angka saja (`628…`). Gunakan nomor uji yang benar-benar milik sales bersangkutan.
5. Sales login dan buka **Inbox → Hubungkan WhatsApp**. Bacalah risiko, pilih persetujuan, pindai QR lewat WhatsApp → Perangkat tertaut. Verifikasi server menuntut nomor gateway cocok dengan nomor akun sales. Hanya sesudah cocok, kirim pesan percobaan dari nomor lain untuk melihat inbox, lalu balas **manual**. Jika nomor tidak cocok, kirim diblokir. Tombol **Putuskan sesi** mencoba logout native; cek juga Perangkat tertaut di ponsel pemilik dan hapus secara manual bila masih tertaut.

Jangan pakai nilai contoh dari `.env.example` sebagai kredensial operasi. Jalankan ulang Compose setelah `.env` diperbarui. `docker compose config --quiet` memeriksa konfigurasi. `docker compose logs api openwa` untuk status umum (hindari menyalin data pelanggan/secret ke tiket). `GET http://127.0.0.1:3001/api/health` memeriksa API/database. Webhook internal `http://api:3001/api/hooks/openwa` **hanya** di jaringan `gateway: internal`, dan `SSRF_ALLOWED_HOSTS=api` mengizinkan tepat host API di gateway tanpa mematikan pelindung SSRF secara global. Gateway juga terhubung ke jaringan `egress` agar tetap dapat menghubungi WhatsApp; jaringan privat saja akan memutus koneksi WhatsApp. API port 3001 dibuka **hanya pada loopback host** untuk proxy Vite; jangan expose ke internet. Gateway tidak memiliki port publik/host, dashboard hanya dapat diakses dari jaringan Docker secara terkontrol bila diperlukan.

Untuk pengembangan API tanpa container, `npm run dev:api` masih bind `127.0.0.1`, tetapi URL webhook Docker `api:3001` tidak dapat menjangkaunya; gunakan API Compose di atas untuk alur lengkap. `OPENWA_URL` dan `OPENWA_WEBHOOK_URL` pada `.env.example` ialah nilai ilustratif untuk proses lokal, sedangkan Compose memasok URL internal yang benar ke API. `OPENWA_API_KEY` dan secret HMAC hanya ada pada environment API/gateway, bukan pada bundle frontend.

## Batas data dan pengamanan

- Pesan masuk yang disimpan: teks dari chat individu nomor terverifikasi; grup, status, media dan pesan dari diri sendiri tidak disimpan. Ingress memeriksa HMAC-SHA256 raw body dan menduplikasi ulang berdasarkan ID gateway. Sales melihat chat sendiri; admin hanya cabangnya; super admin semua. Hanya sales pemilik boleh mengirim balasan. Maksimum daftar 100 chat dan 200 pesan per chat.
- Balasan gateway HTTP `201` berarti **diterima gateway**, bukan terkirim/terbaca di ponsel pelanggan. Kegagalan atau timeout saat kirim dicatat sebagai `unknown`: periksa WhatsApp sebelum mencoba lagi. AI otomatis, broadcast, dan follow-up tidak diaktifkan.
- Pembersihan berjalan pada awal API dan setiap jam: percakapan **tidak dipin** dengan pesan terakhir lebih dari tujuh hari dihapus beserta pesannya. Pin bersifat pengecualian retensi permanen sampai dilepas; periksa kebijakan privasi organisasi sebelum menggunakannya. Audit log minimal tetap ada. Pesan yang belum tampak karena limit 200 tetap terhapus bersama chat saat retensi berjalan.
- Backup **kedua** volume `pgdata` (database aplikasi) dan `openwa_pilot_data` (database dan kredensial sesi gateway). OpenWA menyimpan kredensial sesi sebagai plaintext di volume; batasi akses OS dan backup dengan enkripsi di penyimpanan eksternal. Uji pemulihan pada lingkungan terisolasi, rotasi key bila bocor, dan hapus backup sesuai kebijakan retensi. Menghapus data aplikasi saja tidak menghapus salinan riwayat/kredensial di backup atau gateway.
- Sebelum deployment publik: reverse proxy HTTPS untuk frontend dan `/api`, `APP_ORIGIN` sesuai origin asli, `COOKIE_SECURE=true`, pembatasan IP/akses operator, TLS termination, backup terenkripsi dan audit operasional. `NODE_ENV=production` memaksa cookie HTTPS; konfigurasi lokal dengan HTTP bukan template produksi.

## Pengujian

`npm test` menjalankan unit dan integrasi; integrasi PostgreSQL **hanya** berjalan bila `TEST_DATABASE_URL` terisi database terpisah bernama akhir `_test`. Tes mengosongkan tabel test. Buat misalnya `docker compose exec db createdb -U ruang_sales ruang_sales_test`, lalu isi `TEST_DATABASE_URL=postgres://ruang_sales:<password-encoded>@127.0.0.1:5432/ruang_sales_test` di `.env` sebelum menjalankan tes. `npm run build` memeriksa TypeScript dan frontend; `docker compose config --quiet` memeriksa wiring. Jangan lakukan tes yang memindai QR/mengirim pesan ke pelanggan tanpa izin pemilik nomor uji.

Checklist manual dengan nomor pilot berizin: (1) QR muncul; (2) nomor terverifikasi cocok, nomor salah terblokir; (3) pesan masuk tampil hanya di sales/cabang berwenang; (4) balasan manual diterima di telepon penerima dan statusnya tidak disalahartikan; (5) webhook ulang tidak menduplikasi; (6) logout dan penghapusan tautan pada ponsel; (7) restart gateway lalu sesi pulih atau QR muncul kembali; (8) pin/retensi dan backup/pemulihan di lingkungan terpisah. Sampai checklist ini dilakukan, **pengiriman nyata, pemulihan sesi, dan keamanan nomor belum tervalidasi secara langsung**.

## Demo terpisah

Tanpa `VITE_LIVE_API=1`, frontend lama memakai `localStorage` untuk data contoh; tidak memakai autentikasi API dan **bukan** inbox WhatsApp. Jangan masukkan data pelanggan nyata di mode demo.
